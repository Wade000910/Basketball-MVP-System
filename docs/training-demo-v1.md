# 罰球練習室：產品流程首版與展示腳本

## 本次產出

入口為 [`training/index.html`](../training/index.html)，公開首頁增加「開始罰球練習」按鈕。這一版把設定、逐球記錄、修正、結束報告與歷史回看連成完整流程。可由球員或教練操作，第一批客群仍待實際訪談與試用確認。

已實作：

- 學員代碼、10／20／30 球目標及本組練習重點。
- 命中／未中人工記錄、撤回最後一球、逐球修正與刪除。
- 實際球數、命中率、目標進度與提前結束的標示。
- 本機保存最近 30 組，重新整理後可繼續未完成練習或回看已結束報告。
- 同代碼先前訓練的命中率描述性比較。
- JSON 報告、逐球 CSV，以及瀏覽器列印／另存 PDF。
- 合成示範報告，頁面與匯出均有示範標記，不寫入正式訓練歷史。
- 瀏覽器儲存失敗時明確顯示僅存記憶體；損壞的舊資料不自動覆寫。使用者可明確清除本機紀錄。

訓練頁使用原生 HTML／CSS／JavaScript，沒有 CDN 或資料上傳。它使用瀏覽器本機儲存，尚未提供登入、加密資料庫、跨裝置同步或帳號隔離；共用裝置須留意所有使用者均可看到本機歷史。請勿輸入真實姓名。

## 明天三分鐘展示

1. **30 秒：說明方向。**「我把專題延伸為投籃訓練產品，先完成一次練習的記錄、修正與回顧流程。接下來會驗證教練和球員是否願意持續使用。」
2. **30 秒：先看成果。**開啟罰球練習室，按「先看示範報告」。說明 10 球、7 球命中的 70% 是合成示範，展示報告下載與列印。
3. **60 秒：現場操作。**按「開始新一組」，填 `P001`、10 球與練習重點。人工記錄幾球，示範撤回和修正，再提前結束產生報告。
4. **30 秒：證明可以持續使用。**重新整理，展示紀錄仍在；再做同代碼一組，展示跨次比較。說明差異並非介入效果證明。
5. **30 秒：提出下一步。**展示「開啟相機分析」入口；說明相機分析已能產出時序與品質紀錄，但本次尚未把它與人工命中紀錄自動配對。下一階段是可靠配對、場邊試用、找出使用者願意付費的價值。

沒有網路時可提前把 repository 保存到電腦，以本機 HTTP 伺服器開啟訓練頁。不要只靠 `file://` 的瀏覽器儲存行為，請先試過完整操作並準備下載報告／畫面備份。

## 驗證與界線

- `npm.cmd test`：48/48 Node 測試、既有 HTML 與 Pages 入口檢查通過。
- Chrome headless 真實瀏覽器：設定、示範隔離、記錄、撤回、修正、結束、本機重載、實際 JSON／CSV 下載、同代碼比較、390px 畫面無水平溢位與儲存拒絕情境通過。
- 產生桌面／手機尺寸畫面與合成示範報告 PDF，僅作軟體展示備份。沒有用合成數據冒充實機投籃結果。
- 手機尺寸模擬不等於 iPhone／Android 實機驗收；本次沒有新增人體投籃、相機、音訊或效果研究結果。
- 無自動命中辨識、與相機試次／影片的自動配對、AI 訓練處方、付款或付費意願證據。不宣稱已完成商業產品或證明有人願意購買。

自動檢查使用 `npm test`。瀏覽器測試可設定 `BROWSER_BIN` 為已安裝的 Chrome／Chromium 執行檔，再執行 `node tools/training-browser-smoke.cjs`（Node.js 22 以上）。測試會啟動本機 HTTP 伺服器及隱藏的 headless 瀏覽器，於系統暫存目錄建立獨立瀏覽器設定、截圖與合成下載檔，不使用個人瀏覽器設定。

## 下一階段的產品驗證

找願意試用的教練與球員，觀察首次能否完成一組、記錄操作是否打斷練習、是否回來查看報告，以及是否願意為特定功能付費。先保留使用情境與問題紀錄，再決定自動配對、歷史報告或教練功能的投資順序。
