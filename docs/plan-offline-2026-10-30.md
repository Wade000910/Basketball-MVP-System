# 多組訓練計畫與離線訓練

## 產品流程

- 在單組設定下展開計畫，沿用學員代碼，安排 1–10 組，每組 1–200 球。每組可選投籃類型、位置及練習重點。
- 結束一組後自動建立下一組；組別具有獨立 Session ID、計畫代碼及計畫內組號。
- 提前結束需確認，報告記錄實際球數；零球不可完成組別。結束整份計畫會放棄目前未完成的一組，保留已完成報告。
- 重新開啟頁面接續目前組別。完成後可回看各組、修正投籃紀錄，合計命中率同步重算。
- 下載計畫使用既有備份格式，可匯入並繼續未完成計畫。同計畫再次匯入保留裝置上的進度；其他進行中計畫或練習衝突會拒絕匯入。
- 頁面保留最近一份計畫；各組另存於最近 30 組歷史。計畫自己的已完成報告快照保留至新計畫取代，避免歷史輪替改變合計。

## 儲存與相容性

沿用 `basketball-training-v1` 的單一儲存鍵，新增選用的 `plan`。它採 `basketball-training-plan-v1`，包含固定組別設定、進度、狀態與已完成報告。Session 新增選用的 `planId`／`planStep`；CSV 在原欄位尾端附加這兩欄。

計畫進度、目前練習及歷史在同一次 localStorage 寫入內保存。完整備份包含計畫；單組報告仍可獨立匯入。未完成計畫只允許操作目前組別；完成或結束後才開放回看其他組的報告。

## 離線與安裝

- Service worker 僅管理 `training/`，預載訓練頁、CSS、JavaScript、manifest 與 SVG 圖示，不接管相機、影片回看或其他網站。
- 安裝完成後才顯示離線就緒。預載失敗會清除不完整快取；新的 shell 不自動接管已開啟的舊版練習。
- 每版快取名稱包含 scope 與內容版本。啟用時只移除同 scope 的舊快取，不清除訓練資料或其他應用程式的快取。
- `node tools/update-offline-shell.cjs` 依預載資源內容產生版本；文字換行先統一為 LF，支援 Windows 與 GitHub Linux 發布。測試會核對版本與資源相符。
- 安裝入口使用瀏覽器提供的安裝事件；未提供時顯示 Android／iPhone 的加入主畫面操作說明。無自動安裝、資料上傳或強制重新整理。

## 驗證

- `npm.cmd test`：74 項 Node 測試及 HTML／Pages 檢查。
- Chrome headless：既有訓練、相機摘要、位置與備份流程，加上計畫自動換組、提前結束取消、重新載入、JSON 還原、修正後合計及中途結束保留報告。
- 透過瀏覽器網路離線模式斷線，確認未快取網址請求失敗，再離線重新載入、記錄投籃、切換組別、再次重載與下載完整備份。
- 檢查 manifest、安裝按鈕事件與 service worker scope；390px 手機寬度無水平溢位。
- 安裝按鈕測試不會在主機安裝應用程式；相機測試仍使用合成輸入。測試產物只留在系統暫存目錄。
