# 動作時序準確度驗證流程（慢動作對照）

目的：回答「手機即時分析算出的 Δt，和慢動作影片逐格判斷的 Δt 差多少」。這是專題的對照組，結果寫成 **平均差 ± 標準差、95% 一致性界限、可比較球數**。

工具：[慢動作對照頁](https://wade000910.github.io/Basketball-MVP-System/validation/)（`validation/`），檔案只在瀏覽器處理，不上傳。

## 需要的東西

| 項目 | 說明 |
| --- | --- |
| 分析手機 | 跑罰球動作分析（目前通過測試的是 iPhone 15 Pro） |
| 慢動作手機 | 另一支能拍 240 fps（或 120 fps）的手機，例如 iPhone 慢動作模式 |
| 腳架 2 支 | 兩支手機都要固定，不能手持 |
| 投籃者 | 先用自己；之後若邀請隊友，需取得同意 |

## 拍攝擺位

1. 兩支手機都放在**投籃手那一側的正側面**，距離約 3–4 公尺，高度約腰部，畫面要拍到頭頂到腳、整個手臂。
2. 慢動作手機放在分析手機旁邊（相距 50 公分內），兩者視角盡量一致。
3. 光線充足、背景單純，投籃者穿貼身、和背景顏色不同的衣服。

## 拍攝步驟（一組 20 球）

1. 分析手機：開啟動作分析，選好投籃手，按開始。
2. 慢動作手機：開始錄影（一組錄一段，不要中途停）。
3. 每一球之間停 5 秒以上，讓兩邊都能清楚分開每一球。
4. 投完 20 球後，先停慢動作錄影，再停分析。
5. 分析頁下載「試次 CSV」（或完整資料套件中的 `_live-trials.csv`）。
6. 把慢動作影片傳到電腦。iPhone 用 AirDrop 時請在「選項」開啟「所有照片資料」，保留原始影格率；若傳出來的是慢速播放版本（例如 30 fps），標記頁的「影片檔影格率」填 30。

建議做 **2–3 組，共 40–60 球**。數量太少時，一致性界限會很寬，看不出結論。

## 標記步驟

1. 在電腦開啟慢動作對照頁，選擇影片，填拍攝影格率（240）與影片檔影格率。
2. **先不要載入系統 CSV**，避免看到系統數字影響判斷。
3. 每一球用左右方向鍵逐格找出事件，按數字鍵標記：
   - `1` 膝蓋伸展最快：起跳時膝蓋角度變化最大的那一格
   - `2` 手肘開始伸展：手肘角度開始變大的第一格
   - `3` 手肘伸展最快：手臂推出最快的那一格
   - `4` 球離手：球和手指分開的第一格（用來確認每球對齊）
4. 一球標完按「新增下一球」。頁面會自動暫存；也可以隨時「下載標記檔」備份。
5. 全部標完後，再載入系統試次 CSV。頁面預設依順序配對到系統的有效試次。若系統漏判或誤判一球，在表格中改選對應試次，或勾選「排除」並記下原因。
6. 下載「比較結果 CSV」和「標記檔 JSON」，與原始影片、試次 CSV 一起保存。

## 結果怎麼寫

報告與海報建議放：

- 可比較球數 n（以及總球數、被系統判為無效的球數、排除的球數與原因）。
- **起始定義**與**峰值定義**各自的：平均差（偏差）、差的標準差、95% 一致性界限、平均絕對誤差。
- Bland-Altman 圖（頁面上可直接截圖）。
- 「選定」段落：比較兩種定義的一致性界限，說明哪一種與人工判斷較一致，作為之後顯示與回饋的依據。

範例寫法：

> 共拍攝 60 球，系統判定有效 52 球，其中 2 球因慢動作影片中手臂被遮擋而排除，可比較 50 球。以起始定義計算，系統與人工標記的平均差為 −8.3 ms，95% 一致性界限為 −52.1 至 35.5 ms；以峰值定義計算，平均差為 −3.1 ms，界限為 −28.4 至 22.2 ms。峰值定義的一致性較佳，因此選定峰值定義作為後續指標。

（以上數字僅為格式示範，不是實際結果。）

## 限制（需在報告中說明）

- 對照是**人工逐格判斷**，不是動作捕捉系統；「伸展最快」靠目測判斷，本身也有誤差。可請第二個人獨立標記同一段影片，比較兩人的差異。
- 影格解析度：240 fps 約 4.2 ms，120 fps 約 8.3 ms。
- 只在一支分析手機、一個拍攝角度下驗證，結果不能直接推論到其他手機或角度。
