# 離線逐格檢查頁：首版操作與驗證

入口：[`offline-review/index.html`](../offline-review/index.html)。可以直接以桌面瀏覽器開啟本機檔案，或從本機靜態伺服器載入。頁面沒有 CDN、網路傳輸或持續儲存；來源檔案只在頁面記憶體中讀取，人工標記需自行下載保存。

這是新的獨立檢視頁，沒有修改原有即時程式、投籃狀態機、膝肘分析、品質與聲音回饋。原有已知品質／CV問題仍維持待辦，不宣稱已修正。

## 按步驟使用

1. 開啟入口，一次選取同一 Session 的完整八檔。核對檔案結構、筆數與跨表連結成功後，頁面會載入來源影片。
2. 使用來源記錄滑桿選定一筆來源影格，並在影片中自行找出相同瞬間。按「確認目前來源影格對應目前影片時間」。預設沒有自動時間校正；若無法建立對應，先停止標記。
3. 使用上一筆／下一筆或滑桿，在來源時間點尋址。這是逐筆來源影格檢視，不保證包含所有編碼影格。影片暫停、完成尋址且位於對齊時間範圍後才可標記。
4. 保持「隱藏演算法結果與骨架」勾選，依事先定義的事件準則選擇試次並標記膝部伸展角速度峰值、肘部伸展起始或出手。試次歸屬由人工確認，不能由舊 trial 的日曆時間直接推定來源邊界。
5. 下載人工標記 JSON。每筆保存 Session、試次、來源影格與時間；人工 deltaT 的方向是肘部事件減膝部事件。
6. 如需核對系統，取消隱藏以查看預存骨架、角度訊號、狀態、原 trial 品質與 deltaT 比較。一旦顯示過演算法結果，此次匯出就維持輔助標記狀態；重新勾選不會抹去已接觸結果的紀錄。
7. 換 Session 或改變對齊前先下載。更改對齊會清除本次標記；原始影片與 CSV 不覆寫。

首版優化：左右方向鍵與播放跟隨、已標記事件跳轉、撤銷／重做、JSON重新載入，以及實際呈現影格時間記錄。圖表底圖快取，播放更新集中到動畫影格處理，減少長資料的重複計算。重新載入會檢查Session、版本、來源清單與標記時間；這仍不是原始來源的密碼學證明。

## 資料與量測限制

- 支援既有 `phase1a-local-session-v1` 八檔格式，原匯出格式不變。原格式沒有雜湊；名稱、大小與關聯一致不等於影片內容的來源已被證明。
- 使用實際來源時間而非固定 FPS。來源時間與錄影媒體時間的對應需人工確認；一個對齊點不驗證整段影片的時間漂移。
- 匯出JSON明列單點對齊尚未校正、漂移未驗證及未知不確定度。高影格率影片須核對容許範圍，40ms不能當作逐格或次影格準確度。
- 最近分析資料依來源影格連結與時間容許範圍選取。預設40ms只是可調檢視設定，不是準確度標準；缺失或過遠資料不補造。骨架只在暫停且畫面尋址完成時顯示，並非與播放中每格自動同步。
- 原 trial CSV 沒有膝肘事件各自的來源時間。因此本頁顯示已有結果、允許人工標記，不由 deltaT 推造兩個事件位置。
- 角度圖使用既有 filtered knee/elbow 訊號。人體骨架使用原關鍵點，不新增姿態模型、球路擬合或公尺校正。
- 單純目視標記不能證明角速度峰值或量測真值。正式誤差分析仍需事件準則、獨立標註、時間校正與不確定度評估。
- 這不是完整影片重播重新推論工具，也未實作兩段影片依事件對齊後的視覺疊圖。

## 接下來的驗收順序

1. 用真實資料人工核對影片對齊、首尾時間及中段漂移，再確認瀏覽器實際下載與重新開啟JSON內容。
2. 視需求補兩段影片的事件對齊比較，先為時間映射與各自標记寫測試，再做瀏覽器驗收。
3. 補完整影片重播工具；它必須重新執行本專案方法，與此頁的預存資料檢視分開標示。
4. 原即時系統的必要修正另立工作，先建立失敗案例、修正並跑回歸，再進行手機與實際聲音驗收。

以上未完成項目不因首版軟體檢查通過而視為完成。功能沒有推送、合併或部署到公開網站。
